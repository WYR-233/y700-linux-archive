# 已知坑与作废结论

> 项目跨了整整一个月、几十轮试错，中间产生过大量**当时信、后来被打脸**的结论。
> 这一篇把它们按「当时怎么想 → 为什么错 → 现在的认识」写清楚，
> 目的是让后来的人（包括未来的自己）不要重复同样的弯路。

## 一、被推翻的路线（按时序）

### 1. 「Gunyah 虚拟机是免刷机正路」

- **当时**（09-12）：想用高通 Gunyah hypervisor 在 Android 上跑 Debian VM，不刷机。
- **为什么错**：主线根本不需要 Gunyah 代码。当年真正的障碍只是「内核里没跑喂狗代码」，补丁一打就正常启动。
- **现在**：纯 Linux 直接干掉 Android（09-26 拍板）。

### 2. 「recovery 分区是唯一绕 AVB 的口子」

- **当时**（09-25）：认为 recovery 不校验签名，只能从那儿进。
- **为什么错**：09-26 拿到 AOSP testkey 后，`boot_a` 可以直接刷 Linux。
- **代价**：围绕 recovery 的一整套探索（LZ4 legacy 格式、`kernel_size=0`、ramdisk 拼接）全白费。

### 3. 「刷 boot_a + `fastboot continue` 也能用」

- **当时**（09-24 前）：习惯用 `continue` 接着引导。
- **为什么错**：真实要求是 `fastboot boot`（零写入）或正确签名；`continue` 导致 Load Error 反复。

### 4. 「ABL 只接受 OEM 私钥签名，签名墙不可越」

- **当时**（09-23）：试了各种签名都失败，判定「不可能」。
- **为什么错**：真因是 **footer 缺 prop 描述符**，防降级检查判「版本 0」而拒。
  照抄 3 个 prop + salt + rollback，用 **AOSP testkey 公开私钥**就过。
- **附带纠正**：`vbmeta` 是链式结构、不校验 boot hash，根本不用动。

### 5. 「defconfig + 自改 18 项 + 外部 initramfs + gcc」

- **当时**（09-23 阶段 3.5）：按常规套路改 defconfig。
- **为什么错**：官方答案是 `configs/kernel.config`（327 KB 完整配置）+ **`LLVM=1`** + 空 ramdisk + 内嵌 initramfs。
  defconfig 那条路产出的镜像**根本起不来**。

### 6. 「WCN786x 上游无驱动，WiFi 是唯一硬伤，只能等」

- **当时**（09-12）：翻遍主线找不到驱动，认命。
- **为什么错**：09-26 用 `phy-qcom-pcie2` → `pci-pwrctrl-pwrseq` → rescan → `ath12k` 打通。
  **真凶是 `PCI_PWRCTRL_PWRSEQ` 模块没加载**（芯片没上电）。

### 7. 「Sahara 握手不通 ⇒ 做不了备份」

- **当时**（09-12）：手写 HELLO 协议，收 0 字节。
- **为什么错**：09-23 用刷机匣「回读」导出 17 分区 / 1396 MB。备份根本不是问题。
- **教训**：EDL 手写协议的折腾属于无效投入。

### 8. 「USB 全灭 / 设备卡死」

- **当时**（09-24 前多次误判）：屏幕只活 1 帧，adb/fastboot 都不认。
- **真相**：那是 **Qualcomm Crashdump 模式**，本来就不认 adb/fastboot。

### 9. 「可以改 GPT 划区」

- **当时**（09-26）：想缩 `userdata` 250 G、新建 `linuxroot`。
- **为什么错**：原厂 GPT 条目 CRC 字段指向**另一份空表**，照抄即错 → 整机卡 fastboot。
- **代价**：刷回原厂 GPT + 全量 `.259` 包才救回。
- **现在**：**绝对禁止改 GPT**，只改分区内文件系统。

### 10. 「触摸芯片是 Novatek / 是 NT36536」

- **当时**（09-23）：从 dmesg 看到 `NVTCapacitiveTouchScreen` 就下结论；又误把 `NT36536` 当触控 IC。
- **现在**：官方 DT 有 `st,fts`（FingerTipS）/ `goodix,gt9916S` 三套口径，实机注册的确实是 Novatek；
  **`NT36536` 是显示 DDIC，不是触控 IC**。三口径冲突至今没有定论（需要设备核实）。

### 11. 「Kera = 四代」

- **当时**（09-23）：以为上游地址对不上，设备代号可能叫 `Kera`。
- **现在**：作废。实际 `sun` / `SM8750P` 地址一致，`Kera` 不是本机代号。

## 二、当年的「硬门槛」，现在怎么看

| 当年结论 | 现在 |
| --- | --- |
| 看门狗 37~40 秒必复位，无解 | 误判。是「只有 dts、没有 150 文件代码补丁」的症状；补丁打上正常启动 |
| 必须写 Gunyah 驱动才能跑 | 不需要。主线 7.2.7 + elden 补丁即可 |
| 必须自签 vbmeta / 换 root key | 不需要（换 root key 反而全拒） |
| 屏/触摸/WiFi 全缺驱动，日用无望 | 屏亮了、触摸注册成功（缺固件）、WiFi 通了 |

## 三、硬件层的坑（每条都烧过时间）

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| IRIS 视频硬解 `-110` | `CONFIG_SM_VIDEOCC_8750` 没开 → videocc 不 probe → 拿不到 power-domain | 打开该配置（踩了整整一天） |
| 声卡起不来，`ASoC error (-2)` | 缺 `Lenovo-Y700-Gen4-tplg.bin`（AudioReach 拓扑） | 用 `audioreach-topology` + `m4` + `alsatplg` 生成，sha256 校验 |
| 只有左声道响 | UCM 里 `cset ... 1` 是 pswitch | 改成 `on` / `off` |
| wlan0 变 `unmanaged` | NetworkManager 插件 `.so` 属主不是 root（rootfs 重建导致） | `chown root:root` + `chmod 755` |
| Wi-Fi 连上但没 IP | 热点侧按 MAC 拉黑/隔离 | `cloned-mac-address` 换 MAC |
| 刷 4 GB raw 镜像 `std::bad_alloc` | fastboot 不吃超大 raw | `img2simg` 转 sparse |
| 开机 90 秒 | systemd 等 wlan0；关机 90 秒 = rawshell 的 `TimeoutStopSec` | 配 `JobTimeoutSec` 保险丝 |
| 挂机后自己进 fastboot | ABL 重试额度耗尽（Linux 不报启动成功） | `fastboot set_active a` 续命；正式解药 `qbootctl` |

## 四、留给下一个对话的操作铁律

1. **先备份再动手**；任何刷写前确认 `boot_a_now.img` / `backup_now` 五件套还在。
2. **不改 GPT**；只改分区内文件系统。
3. 报结论前先确认**自己用的工具没错**：
   - `avbtool add_hash_footer`（不是 `add_hashtree_footer`）
   - `fastboot flash` vs `fastboot boot`
   - `LLVM=1`（不是 gcc）
4. 「引导器接受镜像」≠「引导成功」；判断成功要靠**屏幕 / 串口 / pstore** 三条独立证据。
5. 一次只改一个变量；同一个坑试 3 次不成就换工具或停手。
6. 长对话里形成的「铁律」要**回读原始证据**再确认 —— 本项目 36 条翻案里，多半是长上下文里推断被当成实测。
