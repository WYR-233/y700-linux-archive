# 上游与社区现状（2026-11-24 复核）

> 本项目的结论停在 2026-10-13。这一篇是**结项后一个多月**的复核，
> 目的是回答「如果今天再推，还缺什么、别人做到哪了」。
> 信息来自 LKML / GitHub，可能随社区变化而过期；写任何方案前请再查一次。

## 一、一句话结论

**主板级（SoC）支持已经在上游了，板级（elden）还在 review。**
2026-10 之后有一组来自中国科大（USTC）的开发者，正在把 Y700 Gen4 的相机、相机 PMIC
正经地推上游。当年卡住的一半「缺驱动」，今天已经有补丁了 —— 但都还没 merge。

## 二、逐项

### 1. SM8750 平台：已进主线

`arch/arm64/boot/dts/qcom/sm8750.dtsi`、`sm8750-qrd.dts`、`sm8750-mtp.dts`
在 Linux mainline（当前 `7.4-rc4`，2026-11-22）里都存在。
也就是说 CPU / UFS / PCIe / USB / 基础时钟这些平台件，主线已经完整。

### 2. elden 板级 DTS：**未合并，仍在 review**

- 2026-07-19 v1、2026-07-26 v2：[`[PATCH v2 0/2] Introduce Lenovo Legion Y700 Gen4`](https://lkml.iu.edu/2607.3/03457.html)（Pengyu Luo）
  - 已支持：Altmode、背光、电池充电、按键、framebuffer、双 USB 口
  - 当时明确不支持：BT/WiFi、相机、麦克风/扬声器、传感器、振动
- 2026-10-31：[`[PATCH v4 4/4] ... describe the WL2868C regulators`](https://lkml.org/lkml/2026/10/31/309)（Qianhui Xu）
  - 相机 PMIC `willsemi,wl2868c`（i2c10）：后摄 s5kjns、前摄 gc08a8、VCM gt9764 的供电
- 2026-11-04 又出了新版本（[patchew 对比](https://patchew.org/linux/20261104032648.209747-1-xiaqinghuan@mail.ustc.edu.cn/diff/20261106114252.988023-1-xiaqinghuan@mail.ustc.edu.cn/)）

**含义**：本仓库的 `sm8750-lenovo-elden.dts`（2026-10 版）是这条线的分支。
如果社区版本合并了，应以上游为准，本项目只是历史参考。

### 3. 相机：一大步

[`[PATCH v2 0/9] media: camss: add SM8750 support`](https://lkml.iu.edu/hypermail/linux/kernel/2610.3/08810.html)（2026-10-27）

> 原文要点：**在该设备（Lenovo TB322FC）上开发**，前后两个 sensor 都能全分辨率 30 fps 通过 libcamera 出图；
> CSID 接管 VFE 的采集中断（这一代 VFE 没有可用中断）。

这比本项目当年的「libcamera 0.4.0 手动出图、前摄不列」要正规得多。
**当年缺的那部分，社区补上了（待 merge）。**

### 4. 音频：有 codec 驱动，但只做了录音方向

[`[PATCH v2 0/2] ASoC: codecs: add the Qualcomm WCD9378 audio codec`](https://lwn.net/Articles/1086054/)（Jorijn van der Graaf，2026-07-28）

- 已实现：TX/采集（3 个 ADC、4 路模拟输入、麦克风偏置）
- **未实现：RX/播放、MBHC、SmartAMP**（作者写明是后续工作）

注意：Y700 的扬声器走的是 **AW88461 功放 + Secondary MI2S**，不是 WCD9378 的 RX 直出，
所以「播放」这条链和上面的 codec 补丁不完全重合 —— 本项目当年的 AudioReach 拓扑 + UCM2 方案仍然有效。

### 5. ABL 重试额度：有正式解药了

本项目 2026-10-12 实测的机制：Linux 从不向 ABL 报「启动成功」，
`slot-retry-count` 每开机减 1，7 次扣光即 `slot-unbootable=yes`。

**今天的标准答案是 `qbootctl`**：

> Qualcomm A/B boot slot 控制工具，把 Android 的 bootctrl HAL 移植到 Linux，
> 改写 Qualcomm 设备 GPT 分区属性里的 slot 元数据（active / successful / bootable / retry 计数），
> 附带 `qbootctl-mark-successful.service`，在每次到达 multi-user.target 时把当前 slot 标记为成功。

Debian/Ubuntu 有包（`qbootctl 0.2.2-1`），装上 enable 就行。
**这是本项目当年没做、而现在一行 `apt install` 能解决的事。**

### 6. 同机型另一套工程：GEEKiDoS/tb322fc-linux

<https://github.com/GEEKiDoS/tb322fc-linux>

- 最后 commit：**2026-09-12**（之后没更新）
- 但 README 的支持矩阵比本项目当年更完整，而且它是**按「伞形工程」组织的**：
  `sources.json`（源码 URL + 精确 commit）、`firmware.json`（固件路径/大小/sha256）、
  `patches/`（libcamera、hexagonrpc、iio-sensor-proxy）、`configs/`、`initramfs/`、`rootfs/`、`scripts/`
- 它的支持矩阵：

  | 组件 | 状态 |
  | --- | --- |
  | Kernel/UFS | Working（Linux 7.2，ext4 rootfs） |
  | Display | Working（24/40/60/90/120/144/165 Hz） |
  | Touch | Working（Novatek NT36536） |
  | GPU | Working（Adreno 830 + Mesa Turnip + Zink） |
  | Wi-Fi | Working（Peach / ath12k） |
  | Bluetooth | **Partial**（固件能载入，扫描测试失败） |
  | Speakers | Working（AW88461 + AudioReach + UCM） |
  | Haptics | Working（AW86927 ×2） |
  | 加速度/陀螺/光感 | Working（ADSP/SSC，需要打过补丁的 sensor 服务） |
  | Cameras | **Partial**（前后摄能出图，应用与调优待做） |
  | Suspend | **Unreliable**（接 USB 睡眠会中止） |
  | 电池/充电 | **Partial**（充电唤醒与上报有问题） |

- 它明确建议：**`fastboot boot` 零写入测试，不要刷分区** —— 这正是本项目踩到 A/B 额度坑的原因
  （本项目是唯一长期刷 `boot_a` 当日常机的，所以踩到了别人没踩的坑）。

### 7. postmarketOS：还没有 elden

`device/testing/device-lenovo-elden` 不存在（404）。
pmOS 上要等到 elden DTS 进主线 + 有人写 device 包。

## 三、对本项目结论的修正

| 2026-10 的结论 | 2026-11 的看法 |
| --- | --- |
| 「相机主线无支持，优先级最低」 | 已有 CAMSS SM8750 九补丁 + WL2868C，**在路上** |
| 「音频主线无 codec 驱动」 | WCD9378 有 TX 方向驱动；播放仍走本项目方案 |
| 「A/B 额度耗尽只能手动 `set_active`」 | `qbootctl` 可自动化 |
| 「稳定性硬伤无解」 | 仍然没解，但**多了取证手段的可能性**（ramoops、UART） |
| 「蓝牙 95%，RF 零接收」 | 社区同样是 Partial，问题一致 |
